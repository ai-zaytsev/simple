# Нода

Что должно быть на машине, которая обслуживает пользователей.

## Не Путать С Проверочной Нодой

`infra/terraform/cloud-init/node.yaml.tftpl` собирает **проверочную** ноду — эфемерную, для ответа на вопрос «работает ли этот провайдер из России». У неё свой встроенный доступ, потому что Control Plane она не знает и никого не обслуживает.

Боевая нода устроена иначе, и подменять одно другим не следует. Шаблон однажды был почти исправлен «заодно» — и это сломало бы единственное, для чего он существует.

## Контракт Боевой Ноды

**1. Управляющий интерфейс Xray на `127.0.0.1`.**

```json
"api": { "tag": "api", "services": ["HandlerService"] },
"routing": { "rules": [ { "type": "field", "inboundTag": ["api-in"], "outboundTag": "api" } ] }
```

Плюс входящий `api-in`: `dokodemo-door`, `127.0.0.1:10085`. Наружу не выставляется никогда: это список допущенных и власть его менять.

**2. Ни одного доступа в файле конфигурации.**

```json
"settings": { "clients": [], "decryption": "none" }
```

Доступ в файле — это доступ, общий для всех, кто его узнал. Пустой список не означает, что подключиться нельзя: пользователей добавляет агент, на ходу.

Побочное свойство, на которое можно опираться: пользователь, добавленный из файла, не имеет метки, а управляющий интерфейс удаляет по метке. Поэтому агент физически не способен удалить то, чего не добавлял.

**3. Агент, который спрашивает Control Plane.**

```bash
scp node/users-agent.py root@NODE:/tmp/
ssh root@NODE 'umask 077 && cat > /etc/simple-vpn-node.env' <<ENVFILE
CP_URL=https://simple-syncbridge.download
NODE_TOKEN=<32 случайных байта, base64url>
INBOUND_TAG=ws-in
INBOUND_PORT=10000
ENVFILE
scp node/install-users-agent.sh root@NODE:/tmp/
ssh root@NODE 'bash /tmp/install-users-agent.sh'
```

Секрет уходит через stdin, а не аргументом: список аргументов виден любому процессу на машине.

**4. Секрет ноды, записанный в Control Plane хешем.**

```sql
update nodes set token_hash = decode('<sha256 от секрета, hex>', 'hex') where alias = 'n-xxxx';
```

## Проверка

```bash
ssh root@NODE 'xray api inbounduser --server=127.0.0.1:10085 -tag=ws-in'
```

Список должен совпадать с активными доступами в базе. Если нода только что перезапускалась, подождите один цикл: пользователи живут в памяти Xray, а не в файле, и после перезапуска возвращаются следующим проходом агента.

## Перезапуск Xray Не Требует Ничего

Агент сверяет весь список на каждом проходе, поэтому состояние ноды — функция последнего ответа Control Plane, а не её собственной истории. Перезапустить Xray безопасно в любой момент; пользователи вернутся сами.

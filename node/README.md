# Нода

Что должно быть на машине, которая обслуживает пользователей.

## Не Путать С Проверочной Нодой

`infra/terraform/cloud-init/node.yaml.tftpl` собирает **проверочную** ноду — эфемерную, для ответа на вопрос «работает ли этот провайдер из России». У неё свой встроенный доступ, потому что Control Plane она не знает и никого не обслуживает.

Боевая нода устроена иначе, и подменять одно другим не следует. Шаблон однажды был почти исправлен «заодно» — и это сломало бы единственное, для чего он существует.

## Контракт Боевой Ноды

**1. Управляющий интерфейс Xray на `127.0.0.1`.**

```json
"api": { "tag": "api", "services": ["HandlerService"] },
"routing": { "rules": [ { "type": "field", "inboundTag": ["api-in"], "outboundTag": "api" } ] }
```

Плюс входящий `api-in`: `dokodemo-door`, `127.0.0.1:10085`. Наружу не выставляется никогда: это список допущенных и власть его менять.

**2. Ни одного доступа в файле конфигурации.**

```json
"settings": { "clients": [], "decryption": "none" }
```

Доступ в файле — это доступ, общий для всех, кто его узнал. Пустой список не означает, что подключиться нельзя: пользователей добавляет агент, на ходу.

Побочное свойство, на которое можно опираться: пользователь, добавленный из файла, не имеет метки, а управляющий интерфейс удаляет по метке. Поэтому агент физически не способен удалить то, чего не добавлял.

**3. Агент, который спрашивает Control Plane.**

```bash
scp node/users-agent.py root@NODE:/tmp/
ssh root@NODE 'umask 077 && cat > /etc/simple-vpn-node.env' <<ENVFILE
CP_URL=https://simple-syncbridge.download
NODE_TOKEN=<32 случайных байта, base64url>
INBOUND_TAG=ws-in
INBOUND_PORT=10000
ENVFILE
scp node/install-users-agent.sh root@NODE:/tmp/
ssh root@NODE 'bash /tmp/install-users-agent.sh'
```

Секрет уходит через stdin, а не аргументом: список аргументов виден любому процессу на машине.

**4. Секрет ноды, записанный в Control Plane хешем.**

```sql
update nodes set token_hash = decode('<sha256 от секрета, hex>', 'hex') where alias = 'n-xxxx';
```

## Проверка

```bash
ssh root@NODE 'xray api inbounduser --server=127.0.0.1:10085 -tag=ws-in'
```

Список должен совпадать с активными доступами в базе. Если нода только что перезапускалась, подождите один цикл: пользователи живут в памяти Xray, а не в файле, и после перезапуска возвращаются следующим проходом агента.

## Перезапуск Xray Не Требует Ничего

Агент сверяет весь список на каждом проходе, поэтому состояние ноды — функция последнего ответа Control Plane, а не её собственной истории. Перезапустить Xray безопасно в любой момент; пользователи вернутся сами.

## Сертификат

**5. Агент, который держит сертификат свежим.**

Приватный ключ делается на ноде и никогда её не покидает. Наружу уходит запрос на подпись — в нём только публичная половина и имя. Обратно приходит сертификат, документ, предназначенный всем. Взявший машину берёт один сертификат для одной машины; ни другие ноды, ни домены к нему не прилагаются.

Имя берётся не из запроса, а из того, чем нода настроена в Control Plane. Нода, называющая себе домен сама, могла бы попросить доказать владение любым нашим доменом и выдать ей результат.

```bash
ssh root@NODE 'grep -q "^NODE_DOMAIN=" /etc/simple-vpn-node.env || echo "NODE_DOMAIN=example.xyz" >> /etc/simple-vpn-node.env'
scp node/certificate-agent.sh node/install-certificate-agent.sh root@NODE:/tmp/
ssh root@NODE 'bash /tmp/install-certificate-agent.sh'
```

Установщик получает сертификат раньше, чем переставляет пути nginx. Обратный порядок оставляет ноду, чей веб-сервер не стартует: nginx отказывается от конфигурации, называющей несуществующие файлы, а файлы не появятся, пока агент не отработает.

Дальше агент ходит по таймеру раз в сутки, со случайным разбросом до шести часов. Обычно он ничего не выпускает: просьба о ненужном сертификате тратит недельную квоту, а квота — это то, от чего зависит настоящее продление.

### Он Проверяет, Что Сертификат Отдаётся

Не «файл на месте», а «сервер его показывает». Это разные утверждения, и первый выпуск разошёлся ровно по этой границе: сертификат лежал в `/etc/simple-vpn-tls/`, nginx читал `/etc/lego/certificates/`, обе стороны работали правильно, сайт отдавал старый. До истечения старого — почти три месяца — никто бы не узнал.

Проверка идёт на каждом запуске, а не только после выпуска: сертификат, переставший отдаваться, сломан ровно так же, как невыпущенный, и перестать он может в любой день.

```bash
ssh root@NODE '/usr/local/bin/simple-vpn-certificate'
```

Отказ выглядит так и означает, что nginx читает не тот файл:

```
The server is offering a different certificate than the one installed.
  serving:   Nov 23 14:39:57 2026 GMT
  installed: Nov 25 16:10:58 2026 GMT
```

### Снятие Старой Схемы

Нода, переведённая с локального ACME-клиента, до этого шага несёт две дороги к сертификату: агента и старый клиент со своим account key и копией старого приватного ключа. Вторая никому не нужна.

```bash
scp node/retire-http01.sh root@NODE:/tmp/
ssh root@NODE 'bash /tmp/retire-http01.sh'
```

Отдельным шагом, а не установщиком: удаление ключевого материала не должно происходить внутри установочного скрипта между двух других строк вывода. Шаг отказывается что-либо удалять, пока не убедится, что новый сертификат — тот, который получает клиент, и проверяет ещё раз после.

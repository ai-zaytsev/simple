# Plan: One Device, One Link

## Порядок

1. `linksFor` → `linkFor`: розыгрыш ноды через `Rank` от учётных данных, возврат первой пригодной.
2. Ответы API: `link` вместо `links` в трёх местах.
3. `AddExternalDevice`: искать существующее по паре «аккаунт + имя» внутри транзакции.
4. Экран: одна ссылка, показанная сокращённо.

## Риски

**Розыгрыш вернёт ту же ноду после замены.** Тогда «новая ссылка» не чинит того, ради чего её жмут. Закрыто тем, что ключ розыгрыша — учётные данные, которые при замене меняются; тест требует именно этого ключа.

**Все внешние устройства сядут на одну ноду.** Так было бы, если брать первую строку из базы. Ранжирование раскладывает их так же, как телефоны.

**Идемпотентность спрячет настоящую вторую попытку.** Человек, действительно захотевший два устройства с одним именем, получит одно. Это осознанно: два одинаковых имени — это список, из которого нельзя отозвать нужное, а имя здесь и есть способ различить.

## Валидация

Тесты по исходнику: возврат из цикла (а не сбор в список), ключ розыгрыша, поиск до вставки внутри транзакции.

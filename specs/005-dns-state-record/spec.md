# Spec: DNS State Record

- Feature ID: `005-dns-state-record`
- Feature Branch: `feature/005-dns-state-record`
- Status: `implemented`

## Goal

Зафиксировать в durable memory фактическое состояние DNS, установленное запуском `DNS Inventory`, и вывод о том, как правильно проверять Cloudflare-токен.

## Установленные Факты

- `6015874.xyz` и `6015875.xyz` обслуживаются Spaceship, записей нет
- `6047864.xyz` и `6047865.xyz` обслуживаются Cloudflare, записей нет
- `simple-vpn.download` не найден ни у одного из подключённых провайдеров, при этом его DNS работает: почтовый поддомен аутентифицирован в Brevo
- Cloudflare-токен отвечает `401` на `user/tokens/verify` и `200` на `zones`

## Выводы

1. Распределение доменов по провайдерам совпадает с числовым шаблоном имён: пара `6015xxx` у одного провайдера, пара `6047xxx` у другого. Границы шаблона и границы провайдера не должны совпадать.
2. Работоспособность Cloudflare-токена проверяется обращением к `zones`. Проверка через `user/tokens/verify` даёт ложноотрицательный результат на токене, корректно ограниченном зонами и DNS.
3. Автоматизация не управляет `SITE_DOMAIN`, включая его почтовые записи.
4. Создание `A`-записей блокирует не DNS-слой, а невыбранный VPS-провайдер, `ADR-005`.

## Acceptance Criteria

- фактическое состояние и его следствия зафиксированы в durable memory
- правило проверки Cloudflare-токена записано так, чтобы ошибка не повторилась

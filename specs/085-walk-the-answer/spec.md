# Spec: Walk The Answer

Второй живой прогон упал на том же шаге — и опять до создания машины.

## Что Произошло

Список образов у провайдера оказался не плоским: часть элементов — массивы. Выражение, читавшее его как список объектов, споткнулось:

```
jq: error (at <stdin>:57962): Cannot index array with string "os"
```

Машина снова не создалась, денег снова не потрачено, запись ноды удалена.

## Что Изменено

Ответ обходится целиком (`.. | objects`), а не читается как список известной формы. Форма чужого ответа — не то, о чём стоит иметь мнение.

Проверено в обе стороны на образце, воспроизводящем падение: новое выражение находит нужный образ, старое падает той же ошибкой.

## Наблюдение

Две ошибки подряд на одном шаге, и обе — предположения о чужом интерфейсе. Сначала выдуманный идентификатор, затем выдуманная форма ответа. Оба раза написанное собиралось и проходило проверки; узнать можно было только запустив.

Хорошая часть: оба падения случились **до** необратимого шага, потому что порядок выбран так, что дорогое идёт последним. Запись ноды делается заранее именно затем, чтобы падение было чем закрыть.

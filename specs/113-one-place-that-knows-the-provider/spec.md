# Spec: One Place That Knows The Provider

`Retire Node` упал на первом же запуске, молча: `set -e` сработал раньше моего сообщения об ошибке. Причина — я выдумал endpoint получения сведений о машине вместо того, чтобы взять существующий.

Это третий раз за сессию, когда я выдумываю обращение к этому провайдеру, имея рабочий пример в соседнем файле.

## Почему Извинения Здесь Не Работают

Дважды я после такого писал «беру механизм у того, кто уже ходит к этой системе», и дважды через час писал новый вызов заново. Правило, которое я обязуюсь соблюдать, соблюдается ровно до следующего файла.

Значит нужно не правило, а место: если вызов существует один раз, второй раз его нельзя написать иначе, не удалив первый.

## Что Знает `infra/kamatera.sh`

Каждый пункт добыт запуском, и у каждого записано, чем плоха очевидная версия:

- API живёт на `cloudcli.cloudwm.com`, а не там, откуда отдаётся панель;
- идентификатор передаётся в теле, а не в пути, — везде;
- адрес ищется по виду, потому что документированное поле против настоящего ответа возвращает пустоту;
- удаление судится по исчезновению машины из списка, потому что вызов однажды был принят и не сделал ничего.

## Что Осталось

`add-node.yml` и `kamatera-node.yml` по-прежнему знают то же самое по отдельности. Переносить их сейчас, посреди замены нод, значит менять инструмент, которым сию минуту работаешь. Записано в реестр долга.

## Готовность

- `retire-node.yml` ходит к провайдеру только через общий файл
- дублирование записано с условием закрытия

# Spec: Конфигурация должна доезжать до хоста

- Feature ID: `204-the-config-has-to-reach-the-host`
- Feature Branch: `feature/204-the-config-has-to-reach-the-host`
- Status: `local-ready`

## Что Это

Проверка перед выкатом нового домена. Выкат в прежнем виде **сломал бы его**, и по двум причинам сразу.

## Скрипт Не Загружал `nginx.conf`

В архив клались четыре файла содержимого: `index.html`, `404.html`, `styles.css`, `app.js`. Конфигурацию сервера хост держал ту, с которой его построили через cloud-init.

Значит правка `server_name` в репозитории до работающего хоста **не доезжала вообще**. Файл `sites/official/nginx.conf` выглядел источником истины и был им только для нового дроплета.

## Сертификат Выпускался По Неверному Условию

```bash
if ! grep -Eq 'listen.*443' "${nginx_target}"; then certbot ... ; fi
```

Блок 443 на хосте есть — его добавил certbot для прежнего домена. Условие ложно, certbot не запускается, и новое имя обслуживается сертификатом старого. Браузер такую страницу не открывает вовсе.

Условие спрашивало «настроен ли вообще HTTPS», а отвечать должно было «покрыт ли **этот** домен». Разница не видна, пока домен один.

## Почему Ни То, Ни Другое Не Ловилось

Оба про состояние живого хоста, которого в репозитории нет. Ни один тест, ни одно ревью и ни одна из моих проверок не могли их увидеть: смотреть было не на что, кроме файла, который на хост не едет.

Нашлись они потому, что перед выкатом на живой сайт я прочитал шаг за шагом, что именно произойдёт.

## Что Сделано

`nginx.conf` едет вместе с содержимым и устанавливается на хост, с проверкой непустоты перед установкой — обрезанная загрузка не должна обнулить конфигурацию.

certbot запускается **всегда**, с `--reinstall`. Это не расточительно: действительный сертификат переустанавливается, а не перевыпускается, и недельный лимит в пять штук не тратится. Конфигурация из репозитория блока 443 не содержит, поэтому certbot добавляет его каждый раз — ровно как при первом выкате.

`server_name` держит **одно** имя. Вчера я поставил два, чтобы старые ссылки продолжали работать; с `--redirect` это значило бы гнать запрос по старому имени на HTTPS с сертификатом, который его не покрывает — хуже, чем не обслуживать совсем.

Убран `sed`, дописывавший `expires -1` в конфигурацию на хосте: теперь ею владеет репозиторий, и строка там уже есть.

## Границы

Старый домен со следующего выката не обслуживается. Он заблокирован в России, а вне её ссылки на него вели на страницу, которой больше нет по этому имени. Если понадобится — это второй сертификат и второй блок, отдельной работой.

## Готовность

- изменение `nginx.conf` доезжает до работающего хоста
- сертификат выпускается для того домена, который обслуживается
- пустая или обрезанная конфигурация не устанавливается

# Plan: Релиз без старого имени

## Порядок

1. Адрес поддержки и версия.
2. Соглашение об имени файла — с поимённым исключением для 0.1.0.
3. Тест: перевести отрицательные проверки на новые имена, добавить пару «старое имя отвергнуто / новое принято».
4. Мердж, публикация 0.1.1.
5. Проверить: ссылка в Core на новом домене и без слова, архив на сайте, 0.1.0 по-прежнему скачивается.

## Риски

**Публикация упадёт на собственном архиве.** Ровно это случилось бы при смене соглашения в лоб. Закрыто поимённым исключением.

**Отрицательный тест пройдёт по чужой причине.** Три существующих так бы и проходили. Переведены; новая проверка стоит в паре с положительной.

**Необратимость.** Опубликованная версия остаётся в архиве навсегда, поэтому имя решено до публикации, а не после.

## Валидация

Тест публикации гоняет baseline через `check-site.sh`. Сборку и unit-тесты приложения — Android Build. Настоящая проверка — сама публикация и чтение Core после неё.

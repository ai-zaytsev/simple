# Spec: ASCII-only Cloud Init

- Feature ID: `021-cloud-init-ascii`
- Feature Branch: `feature/021-cloud-init-ascii`
- Status: `in-progress`

## Найденная Причина

Три подряд прогона не поднимали ноду. Диагностика по SSH показала картину, которая выглядела как исправная машина: `cloud-init status` сообщал `done`, память была свободна, SSH работал. При этом ни одного нашего файла на ноде не существовало, а порты 80 и 443 были закрыты.

Расширенный статус объяснил всё:

```
Failed loading yaml blob. unacceptable character #x0082
Failed at merging in cloud config part from part-001: empty cloud config
```

Файл в репозитории при этом корректен: искажение происходит при передаче user-data, а не в git.

## Что Сделало Отказ Дорогим

Ни одна сторона не сообщила об ошибке. Terraform отработал успешно, провайдер создал машину, cloud-init отчитался `done`, машина отвечала по SSH. Единственным симптомом было отсутствие результата.

Существенно и то, что `index.html` уцелел: он передавался base64 и потому не содержал ни одного не-ASCII байта в самом документе. Разница между уцелевшим файлом и испорченным и указала на причину.

## Решение

**Шаблон cloud-init содержит только ASCII.** Весь текст с не-ASCII символами живёт в `sites/` и передаётся через base64, как уже передавался сайт. 404-страница вынесена в `sites/pigeons/404.html`.

**Правило проверяется автоматически.** В `Baseline Checks` добавлен шаг, который читает шаблоны побайтово и падает при первом байте больше 127. Правило, которое нельзя проверить, будет нарушено при первой же правке.

**Причина зафиксирована в шапке шаблона**, чтобы следующий редактор не восстановил встроенный текст.

## Что Проверено Локально

Отрендеренный user-data: 26 383 байта, не-ASCII байтов ноль, YAML валиден, нерешённых подстановок нет.

## Acceptance Criteria

- шаблон не содержит не-ASCII байтов
- проверка в CI падает при их появлении
- нода доходит до `ready`

## Validation

- локальный рендер с учётом экранирования `$${`
- фактический прогон

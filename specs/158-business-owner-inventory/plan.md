# Plan: Инвентаризация системы для Business Owner

- Feature ID: `158-business-owner-inventory`
- Feature Branch: `feature/158-business-owner-inventory`
- Owner: `orchestrator`

1. Собрать все текущие BO-описания, инфраструктурные факты, панели, runbook и правила масштабирования.
2. Сверить документированные сведения с конфигурацией и доступными живыми источниками без чтения секретных значений.
3. Создать единый BO-операционный документ с явными границами источника истины.
4. Удалить дубли и заменить их ссылками, сохранив уникальные технические детали для разработчиков.
5. Проверить ссылки, отсутствие противоречий и секретов, затем провести PR loop.

## Risks

- Часть провайдерских или региональных сведений может быть устаревшей; неподтверждённое должно быть явно отмечено, а не угадано.
- Чрезмерная дедупликация может удалить полезные developer-specific детали; переносится только BO-операционный слой.
- Панель или внешний сервис может требовать авторизацию; в документе допустима ссылка без секретов.

## Validation

- Поиск одинаковых BO-инструкций и старых значений по всему `docs/`.
- Проверка всех относительных ссылок.
- Проверка документа на шаблоны секретов и реальные credential-like значения.
- `git diff --check` и repository checks через PR.

## Implementation Result

- Единый источник создан в `docs/business-owner-operations.md`.
- Инвентарь сверен с Read The Panel, Infra Inventory, DNS Inventory, provider/API evidence и публичными HTTPS probes 2026-08-31.
- Старые provider/topology/monitoring/backup/runbook snapshots удалены или превращены в technical contracts со ссылкой на BO-документ.
- DNS Inventory дополнен стабильным доменом Core.
- Не реализованные backup, log archive, host monitoring и FREE quota записаны как долг; авария APK-сайта — как release blocker.

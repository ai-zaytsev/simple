# Plan: Deferred Stack Migration And FREE Limits

- Feature ID: `010-deferred-stack-and-limits`
- Feature Branch: `feature/010-deferred-stack-and-limits`
- Owner: `orchestrator`

## Implementation Slices

1. План перехода на ClickHouse и Loki: инварианты формата и процедуры сверки.
2. Лимиты FREE: значения, точка применения, механизм шейпинга, честный статус механизма.
3. Согласование остальных документов с фактическими хранилищами.
4. Скелет Terraform с remote state и бюджетным guard.
5. Workflow проверки Terraform с инвентаризацией SSH-ключей.

## Порядок Не Случаен

Инварианты формата идут первыми, потому что они ограничивают схему аналитики и формат логов, которые появятся в коде следующей стадии. Написать код раньше ограничений означает переписывать данные, а данные переписать нельзя.

## Risks

- механизм ограничения скорости не проверен на железе: зафиксирован как незакрытое требование, а не как решение
- инварианты переноса легко нарушить незаметно: для каждого назван автоматический тест
- Loki молча отбрасывает записи старше порога: это отдельно выделено в плане миграции, потому что импорт при этом выглядит успешным
- бюджетный guard опирается на прайс, скопированный в код: при смене цен провайдером оценка разойдётся с фактом

## Validation Plan

- `terraform fmt -check`, `init` против реального backend, `validate`, `plan`
- проверка отсутствия упоминаний ClickHouse и Loki как развёрнутых компонентов
- проверка перекрёстных ссылок между документами

## Merge Readiness

Задача закрывается, когда план миграции зафиксирован, лимиты описаны, а Terraform инициализируется против Spaces и проходит бюджетную проверку.

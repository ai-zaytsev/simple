# Plan: Trace On Request

## Порядок

1. Уровень логирования становится свойством намерения, а не наличия файла.
2. Три файла разъезжаются по сроку жизни.
3. Состояние записи появляется отдельно от состояния подключения.
4. Экран: кнопка в углу, предупреждение, индикатор, отправка с числом.
5. Тесты закрепляют обе стороны: обычные режимы не называют адресов, запись — называет.

## Риски

**Запись переживает намерение.** Главный. Закрыт не напоминанием: жёсткий автостоп через 10 минут без продления, остановка при OFF, удаление при запуске приложения.

**Отправка не того файла.** Обычный лог и запись стоят в разных местах экрана и называются по-разному. Отправка записи проходит через диалог с числом адресов.

**Запись переживает процесс.** Состояние записи живёт в процессе; если процесс умер, при следующем открытии приложения файл удаляется до того, как его кто-то предложит отправить.

**Перезапуск движка ломает сессию.** Используется тот же путь, что и при failover: интерфейс остаётся, перезапускается только движок.

## Валидация

- Тест: `Off` и `Errors` не дают уровня, называющего адреса; `Trace` даёт.
- Тест: наличие файла не поднимает уровень.
- Тест: запись пишет в свой файл, обычный лог — в свой.
- На устройстве: включить, увидеть счётчик, дождаться автостопа, отправить, убедиться что предложение отправки исчезло.

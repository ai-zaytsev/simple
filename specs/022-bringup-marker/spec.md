# Spec: Distinct Bring-up Completion Marker

- Feature ID: `022-bringup-marker`
- Feature Branch: `feature/022-bringup-marker`
- Status: `in-progress`

## Что Заработало

Перевод шаблона в ASCII снял отказ cloud-init. Нода впервые применила конфигурацию: Nginx поднялся, Xray запустился, собственный адрес определился.

## Что Сломалось Следующим

Прогон объявил ноду готовой через полторы минуты после создания и пошёл проверять сайт, которого ещё не было: сертификат в этот момент не был выпущен.

Причина в моей проверке ожидания. Файл статуса накапливает строки, а условие искало подстроку `ready`. Она встречается в промежуточных состояниях `packages-ready` и `dns-ready`, поэтому первое же из них выглядело как завершение.

## Решение

Терминальное состояние получило собственное имя `bringup-complete`, не пересекающееся с промежуточными. Условие ожидания ищет именно его.

Общее правило, стоящее за этим: **признак завершения не должен быть подстрокой признака прогресса.** Накопительный лог превращает совпадение по подстроке в ложное срабатывание, и оно тем опаснее, чем раньше в списке встречается.

## Acceptance Criteria

- ожидание завершается только на терминальном состоянии
- прогон доходит до проверки сайта с выпущенным сертификатом

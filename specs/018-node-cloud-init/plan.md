2. Terraform: переменные ноды, предусловие на staging-контур.
3. Workflow: генерация учётных данных, создание, DNS-запись, ожидание, четыре проверки, уборка.
4. Прогон и разбор.

## Почему Нода Публикует Прогресс

Без доступа по SSH из CI отказ на середине bring-up выглядит как чёрный ящик. Нода пишет прогресс в `/status.txt`, workflow его опрашивает и при отказе называет шаг, а не строит догадки.

Файл появляется только на проверочных нодах: в проде он описывал бы наш bring-up любому желающему.

## Risks

- bring-up ждёт, пока DNS начнёт указывать на ноду: при задержке распространения ожидание упрётся в таймаут
- staging-сертификат не доверен по умолчанию: клиент проверки добавляет корень staging, а не отключает проверку
- REALITY на отдельном порту в прошлый раз не заработал, причина не установлена: его отказ не отменяет результата по основному транспорту
- `if` внутри `location` в Nginx применим ограниченно, здесь используется только `return`, что является безопасным случаем

# Plan: VIP Has No Ceiling

## Порядок

1. Миграция `0018`: снять `not null` и проверку из `0005`, поставить VIP оба предела в `null`.
2. Выселение: читать предел в указатель, при `nil` не выселять никого — и выходить **до** запроса, потому что запрос вычитает из предела единицу.
3. Добавление внешнего устройства: сравнивать только когда предел есть.
4. `AccountTier`: пределы становятся указателями, добавляется `MaxExternal`.
5. API отдаёт `null` там, где предела нет.

## Риски

**Ноль прочитан как «без предела» или наоборот.** Самый дорогой из двух — тихий: VIP не может добавить телевизор. Прикрыто тестом, который требует проверки на `nil` в обоих местах.

**Проверка из `0005` осталась бы.** Столбец nullable, а проверка требует `>= 1` — `null` в проверке даёт unknown и проходит, но полагаться на это не стоит: проверка заменена явной, разрешающей `null`.

**FREE задет случайно.** Миграция трогает только строку VIP; тест на `max_external = 0 where tier = 'FREE'` из `0015` остаётся и продолжает это стеречь.

## Валидация

Тесты по тексту схемы и исходника — так в этом проекте проверяются миграции, потому что политика живёт в строках, а не в Go: тест кода прошёл бы, пока строки говорят другое.

После выката — панель, и проверка, что FREE по-прежнему держится на десяти мегабитах. Предел VIP проверить сейчас нечем: живой VIP-аккаунт один, и он же тестовый.

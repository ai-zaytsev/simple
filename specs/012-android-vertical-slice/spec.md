# Spec: Android VPN Vertical Slice

- Feature ID: `012-android-vertical-slice`
- Feature Branch: `feature/012-android-vertical-slice`
- Status: `in-progress`

## Goal

Получить первый Android APK, устанавливающий VPN-соединение через VLESS/REALITY endpoint, с интерфейсом из одной кнопки и умной маршрутизацией без участия пользователя.

## Scope

- `android/` — проект приложения
- `.github/workflows/android-build.yml` — сборка APK
- `.github/workflows/libxray-build.yml` — сборка движка из исходников XTLS
- `docs/architecture/android-client.md`
- `ADR-020`, `ADR-021`

## Что Сделано

| Критерий приёмки | Состояние |
| --- | --- |
| ON устанавливает VPN | Путь реализован, не проверен: движок не привязан и нет endpoint |
| OFF корректно выключает | Реализовано |
| Нет VPN loop | Реализовано: приложение исключает себя из туннеля |
| Нет очевидного DNS leak | Реализовано: DNS внутрь туннеля, проксируемые имена по DoH |
| Ошибка Xray не роняет приложение | Реализовано: отказ движка это состояние, а не исключение |
| Закрытие Activity не ломает работу | Реализовано: туннель в сервисе, состояние на уровне процесса |
| Переход Wi-Fi и мобильной сети | Реализовано: перезапуск движка при смене нижележащей сети |
| Воспроизводимая сборка APK | Реализовано для отладочной сборки, побитовой идентичности релиза нет |

## Два Незакрытых Пункта

**Движок не привязан.** `PendingXrayEngine` отказывается стартовать и сообщает причину. Привязка пишется по фактической публичной сигнатуре AAR, которую печатает workflow `libXray Build`. Писать её по памяти означает получить либо несобирающийся код, либо собирающийся и неверный.

**Нет endpoint.** Развёрнутых VPN-нод не существует: Стадия 1 закончилась с нулём дроплетов. Профиль читается из ассета, которого нет в репозитории, потому что он содержит рабочий credential и адрес ноды.

Оба пункта означают одно: `ON` сейчас честно сообщает, что подключиться нечем, вместо того чтобы имитировать соединение.

## Non-Goals

- не подключать Control Plane: его нет, профиль временно локальный
- не публиковать релизную сборку: keystore у Business Owner
- не составлять полные списки маршрутизации по памяти

## Acceptance Criteria

- проект собирается в CI и даёт APK с записанным SHA-256
- состояние соединения никогда не сообщает об успехе без туннеля
- транспорт изолирован за одним интерфейсом
- маршрутизация реализована двумя уровнями и описана

## Validation

- сборка `Android Build` на PR
- запуск `libXray Build` и получение публичной сигнатуры
- проверка на устройстве после привязки движка и появления endpoint

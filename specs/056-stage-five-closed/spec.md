# Spec: Stage Five Closed

Запись закрытия стадии. Кода не меняет.

## Требования Стадии И Чем Они Подтверждены

| Требование | Подтверждение |
| --- | --- |
| Нельзя один общий доступ на всех FREE | В конфигурации нод ноль доступов; каждый выдан устройству |
| Нельзя один общий доступ на аккаунт | Лимит FREE — одно устройство, остальные отключаются |
| Свой идентификатор у устройства | Был и остался |
| Свой VPN-доступ у устройства | Свой VLESS-идентификатор, зарегистрирован на всех нодах |
| Доступ можно отдельно отозвать | Проверено на живых нодах: отозванный исчез с обеих, второй остался |
| Аналитика отделена от почты и доступа | В логах только ключ, выведенный из аккаунта и необратимый между эпохами |
| Одно устройство отключается отдельно | Проверено на двух телефонах, в обе стороны |
| Остальные устройства работают | Проверено на пробных устройствах: отозвано одно, второе не тронуто |
| Утечка одного не раскрывает других | Доступы независимы; общих не осталось |
| Нельзя выдать себя за другое подменой идентификатора | 401 без секрета, 401 с идентификатором в теле, 401 с выдуманным секретом |

Плюс два долга, закрытых внутри стадии: выключатель и переход на резерв. См. [../053-stage-five-accepted/spec.md](../053-stage-five-accepted/spec.md).

## Четыре Ошибки, Найденные Проверкой

Ни одну не нашло бы чтение кода.

**Проверка ноды спрашивала про порт, а не про туннель.** Порт принадлежит Nginx: нода с мёртвым движком проходила бы её. Нашлось при подготовке к тесту — вопросом «а что именно я сейчас уроню и заметит ли это телефон».

**Два числа на один вопрос.** Клиент просыпался каждые пять минут, считал документ свежим пятнадцать и не спрашивал сервер. Выключатель сработал за тринадцать минут вместо пяти. Нашлось человеком, который ждал.

**План запрашивался только когда устаревал.** Отключённое устройство со свежим планом подключилось бы на доступе, который ни одна нода не принимает. Нашлось при разборе того, как устройство узнаёт об отключении.

**Секрет выдавался по подтверждённой попытке.** Отключённое устройство могло опросить старую ссылку и вернуть себе доступ. Нашлось прогоном правила через настоящие эндпоинты.

Общее у всех четырёх: механизм существует, выглядит рабочим и не делает того, ради чего написан. Такие ошибки находит только исполнение — и человек, который ждёт результата.

## Что Осталось Незакрытым Осознанно

**Окно между потерей связи и объяснением.** Нода узнаёт об отзыве за десять секунд, приложение — за пять минут. Business Owner принял: спрашивать чаще стоит заряда.

**Отладочная выгрузка логов.** Business Owner снял её из блокеров: выкатка в production не планируется, идёт разработка.

**Экран своих устройств.** API есть (`/v1/devices`, `/v1/devices/revoke`), экрана нет. Понадобится, когда лимит станет больше единицы.

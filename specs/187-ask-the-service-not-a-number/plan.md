# Plan: Спрашивать сервис, а не число

## Порядок

1. Заменить сравнение кода на проверку тела в обоих workflow.
2. Печатать ответ сервиса при отказе.
3. Указать в отказе рабочий способ отката.
4. Закрепить контракт `/healthz` тестом.

## Риски

**Тело изменится.** Тогда упадёт тест, а не молча соврут три workflow. Это и есть смысл правки.

**`ok` встретится случайно.** Совпадение ищется в ответе `/healthz`, который либо `{"status":"ok"}`, либо пустой, либо ошибка. Случайного `ok` там взяться неоткуда.

**Проверка станет слабее кода состояния.** Станет сильнее: код `200` отдаёт и страница-заглушка, а слово `ok` — только этот обработчик.

## Валидация

Тест на контракт выполняется в baseline. Сама проверка проверяется следующим восстановлением или откатом — отдельного прогона ради неё не будет.

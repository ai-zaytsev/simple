# Plan: DNS Automation

- Feature ID: `003-dns-automation`
- Feature Branch: `feature/003-dns-automation`
- Owner: `orchestrator`

## Implementation Slices

1. Завести repository variables с ролями доменов.
2. Добавить read-only workflow инвентаризации по обоим провайдерам.
3. Зафиксировать контракт DNS в `docs/integrations/dns.md`.
4. Смержить, запустить, разобрать фактическое состояние записей.

## Почему Сначала Read-Only

Записи `A` создавать не для чего: серверов нет. Но проверить доступ, выяснить распределение доменов по провайдерам и убедиться в отсутствии проксирования нужно до того, как появятся IP. Обратный порядок означал бы отладку DNS в момент, когда от него уже зависит работа сервиса.

## Risks

- проксирование Cloudflare на точке входа ломает REALITY полностью, а не частично
- домены `vpn-entry` образуют угадываемый числовой шаблон: раскрытие одного облегчает перебор остальных
- у Spaceship нет отдельного эндпоинта проверки учётных данных, поэтому проверка выполняется пробным запросом к первому домену
- новые workflow в этом репозитории обязаны быть в ASCII без `inputs`, иначе GitHub молча их не регистрирует, см. `specs/002-email-provider-integration/spec.md`

## Validation Plan

- локальная YAML-валидация и проверка ASCII
- фактический запуск после merge
- сверка результата инвентаризации с ожидаемыми ролями доменов

## Merge Readiness

Задача закрывается, когда инвентаризация отработала, распределение доменов по провайдерам известно, а отсутствие проксирования подтверждено.

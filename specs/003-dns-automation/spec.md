# Spec: DNS Automation

- Feature ID: `003-dns-automation`
- Feature Branch: `feature/003-dns-automation`
- Status: `in-progress`

## Goal

Подключить автоматизацию DNS для инфраструктуры MVP через API Cloudflare и Spaceship, зафиксировать роли доменов и конвенции записей, и обеспечить проверку состояния до того, как появятся серверы.

## Non-Goals

- не создавать `A`-записи для точек входа: серверов ещё нет, VPS-провайдер не выбран (`ADR-005`)
- не регистрировать, не продлевать и не переносить домены
- не менять nameservers
- не трогать записи, не относящиеся к ролям `vpn-entry` и `site`

## Scope

- `.github/workflows/dns-inventory.yml`
- `docs/integrations/dns.md`
- repository variables `VPN_ENTRY_DOMAINS`, `SITE_DOMAIN`
- `specs/003-dns-automation/`

## Роли Доменов

| Роль | Домены | Назначение |
| --- | --- | --- |
| `vpn-entry` | четыре `.xyz` | Точки входа `https-direct` для API Control Plane, попадают в seed APK |
| `site` | `simple-vpn.download` | Сайт для скачивания APK и почтовый поддомен Brevo |

Разделение обязательно: домен сайта рекламируется и будет заблокирован первым. Если бы на нём жил API Control Plane, блокировка сайта убивала бы сервис целиком.

## Ключевое Ограничение

Cloudflare proxy для `vpn-entry` записей должен быть выключен. Проксирование терминирует TLS на стороне Cloudflare и делает VLESS + REALITY полностью неработоспособным. Это самая вероятная операционная ошибка DNS-части, потому что проксирование включается по умолчанию при создании записи через панель.

## Acceptance Criteria

- учётные данные обоих провайдеров проверяются автоматически
- известно, какой провайдер обслуживает какой домен
- проксированная запись на `vpn-entry` домене приводит к падению проверки
- в публичные логи не попадают токены и идентификатор аккаунта
- роли доменов и конвенции записей задокументированы

## Validation

- YAML-валидация и проверка на отсутствие не-ASCII
- фактический запуск `DNS Inventory` после merge
- `Process Baseline`, `PR Loop Guard`, `AI Review` зелёные

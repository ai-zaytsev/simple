## APK Опубликована

Публикация `0.1.0 (1)` **состоялась**. Проверено напрямую по официальному домену:

- `/releases.json`: `latest = 0.1.0`, versionCode 1, `publishedAt 2026-09-01T13:43:57Z`, commit `54a2d5a`;
- `/download/latest.apk`: HTTP 200, 56 599 049 байт, SHA-256 `e99ce3d9…` — **совпадает с манифестом**;
- `/download/releases/0.1.0/simple-vpn-0.1.0.apk`: HTTP 200.

Запуск при этом помечен неудачным, и это не противоречие: он упал **после** загрузки, на повторном чтении сертификата у публичной копии.

## Тот Же Дефект, Второй Экземпляр

Разбор вывода `apksigner` был написан **дважды**: перед загрузкой и при публичной проверке. Обе копии несли один и тот же привязанный шаблон `Signer #1 certificate SHA-256 digest:`, который на нынешних build-tools не совпадает ни с чем — они печатают по блоку на диапазон SDK.

Я починил ту копию, что упала первой. Запуск прошёл дальше и упал на второй, тем же самым образом.

**Дефектом был не шаблон, а две копии одного правила.** Шаблон — только то, как это проявилось.

Теперь чтение живёт в `.github/scripts/apk-certificate.sh`, и оба шага зовут его.

## Почему Опубликованному Можно Верить, Хотя Проверка Упала

Сверка отпечатка у публичной копии — защита в глубину, а не единственное доказательство. Байты публичного файла совпадают с байтами того артефакта, чей сертификат был прочитан **до** загрузки: SHA-256 сошёлся. Одинаковые байты несут одинаковую подпись.

То есть упавшая проверка не оставила сомнений в подлинности — она оставила невыполненным следующий шаг.

## Что Осталось Невыполненным

`Advance Core latest after public verification` — регистрация релиза в Control Plane каналом `direct_apk`. Сайт про релиз знает, Core — ещё нет.

Повторный запуск для этого предусмотрен самим workflow: он обнаруживает уже опубликованный релиз, **отказывается перезаписывать** неизменяемые байты, переиспользует личность релиза и продолжает как синхронизацию с Core. Сверяется и сертификат — то есть повторная сборка не может подменить ключ незаметно.

## Границы

Сообщение о несовпадении теперь печатает оба отпечатка. Прежнее говорило «mismatch» и не показывало ни одного, что при пустой строке слева выглядело как подменённый файл, а было пустым разбором.

## Готовность

- одно место читает подпись, вызывается из обоих шагов
- при несовпадении видно оба значения
- релиз зарегистрирован в Core

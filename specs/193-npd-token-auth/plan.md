# Plan: Беспарольная авторизация НПД

## Порядок

1. Снять поток входа по паре с `grandvan709/yookassa-to-mynalog`, дописать в `docs/integrations/lknpd.md`.
2. `Credentials` — пара рядом с ИНН и паролем, стартовать при любом из двух.
3. `LoadSession` принимает выданный `deviceId` и не генерирует поверх него.
4. `renew` — порядок попыток, с остановкой на недоступности.
5. `Profile` в адаптере: узнать ИНН, когда настроена только пара.
6. Выкат: два секрета, отказ на полупаре.

## Риски

**Начали с семени вместо ротированного токена.** Предъявили бы уже потраченный. Закрыто порядком: сохранённый первым, тест на второй проход.

**Перебор способов у лежащей ФНС.** Повторные входы в неофициальный API — путь к CAPTCHA. Недоступность прекращает попытки немедленно; есть тест, что при ней вход по паролю не делается вообще.

**Сгенерированный `deviceId` рядом с чужим токеном.** Отказ выглядел бы как отозванный токен и увёл бы искать не туда. Настроенный перекрывает всё; есть тест, что store спрашивают именно про него.

**Смена пары не подействует без правки базы.** Подействует: при отказе сохранённого пробуется настроенный.

**Неизвестный ИНН ломает адрес чека.** Спрашивается у `/user` один раз и сохраняется; есть тест, что второй раз не спрашивается.

**Полупара в секретах.** Токен без идентификатора отклонят, и это прочтётся как отозванный токен. Выкат отказывается раньше.

## Валидация

`go build`, `go vet`, `go test ./...` зелёные. Шаг выката проверен `bash -n` отдельно, потому что новая ветвистость в нём — единственное место, которое не проверяет ни компилятор, ни тесты.

Живой проверки здесь нет: настоящая — первая утренняя проверка на боевом Core с заведённой парой.

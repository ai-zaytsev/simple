# Spec: Проверка путей входа с пользовательского устройства

- Feature ID: `155-way-in-device-acceptance`
- Feature Branch: `feature/155-way-in-device-acceptance`
- Status: `in-progress`

## Goal

Снять релизный блокер «Путь входа один и не проверен оттуда, откуда важно»: каждое включённое публичное entry должно проверяться Android-приложением напрямую с пользовательского устройства, а результат должен быть принят Core и виден в панели без сбора адресов посещаемых пользователем сайтов.

## Placement Decision

Новый сервер и новый домен не нужны. Живой подписанный bootstrap уже содержит четыре пути входа: стабильный домен, прямой IP и два edge-домена. Остановленный HTTPS-сервис одного edge восстановлен штатным `Update Node`; все четыре точных bootstrap URL отвечают из внешней точки. Дополнительный Droplet не улучшит приёмку, пока существующие пути не измеряются приложением.

## Acceptance Criteria

- Android проверяет каждое distinct entry из подписанного bootstrap, а не только случайно выбранный рабочий путь.
- Проверки выполняются без VPN-туннеля и поэтому отражают доступность входа из пользовательской сети.
- Core принимает результаты только для собственных включённых entry и VPN-узлов.
- В отчёт попадает только host нашего пути входа; адреса сайтов, которые посещал пользователь, не собираются.
- Проверка ограничена по частоте, не блокирует UI и повторяется после первого входа в аккаунт.
- Неисправный включённый edge восстановлен либо отключён штатно.
- Test APK установлен на реальное целевое устройство; панель показывает device checks для каждого включённого пути.
- Required checks и AI review зелёные на текущем PR head, merge authority остаётся у человека.

## Non-Goals

- Публикация официального APK до снятия общих release blockers.
- Сбор URL или доменов пользовательского трафика.
- Подъём дополнительной инфраструктуры при наличии минимум двух независимых рабочих путей.

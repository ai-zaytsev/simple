# Plan: A Speed That Differs

## Порядок

1. Скорость на тариф в схеме; `null` — без предела.
2. Список ограниченных учёток и одна цифра — тем же путём, что список тяжёлых.
3. Outbound с меткой и порядок правил.
4. Шейпер по метке, обе стороны.
5. Агент применяет список и ставит шейпер каждый круг.

## Риски

**Предел записан и не применён.** Самый вероятный исход, если порядок правил перепутать: широкое правило отвечает первым, узкие мертвы. Порядок задан одним списком в одном месте.

**Ограничена только отдача.** Обратные пакеты не несут метки, поэтому она сохраняется и восстанавливается по соединению. Иначе предел был бы незаметен там, где его замечают.

**Задеть администрирование.** Класс по умолчанию — вся полоса; ограничивается только помеченное. Не список исключений, который однажды окажется неполным.

**Потерять смесь трафика.** `slow-` складывается обратно в тот же класс, иначе трафик большинства пользователей исчез бы из отчёта.

**Шейпер исчезнет после перезагрузки.** Ставится каждый круг, а не при изменении.

## Валидация

- порядок правил: узкие раньше широких, на таблице случаев
- `slow-` складывается в тот же класс
- живая: измерить скорость на FREE и на VIP

# Spec: Spaces Retention Decision

- Feature ID: `009-spaces-retention-decision`
- Feature Branch: `feature/009-spaces-retention-decision`
- Status: `implemented`

## Goal

Зафиксировать установленную границу прав ключей Spaces и принятое решение о том, как выполнять требование retention без расширения прав.

## Установленные Факты

| Операция | Результат |
| --- | --- |
| `PutObject`, `GetObject`, `DeleteObject`, `HeadBucket`, `ListObjectsV2` | Работают |
| `PutBucketVersioning` | `AccessDenied` |
| `PutBucketLifecycleConfiguration`, обе формы | `AccessDenied` |

Round-trip запись, чтение обратно и удаление подтверждены.

## Решение

Более широкий ключ Spaces **не запрашивается**. Требование «шифрование, минимально достаточный retention и проверка восстановления» выполняется имеющимися правами:

- шифрование обеспечивается платформой, дополнительно бэкап шифруется на стороне Core до загрузки
- retention реализуется бэкапным заданием: удаление объектов старше окна хранения
- ключи объектов содержат метку времени, перезаписи не происходит, поэтому versioning для защиты бэкапов не нужен
- проверка восстановления делается отдельной задачей, а не считается выполненной по факту наличия файла

## Что Теряется

История версий для state Terraform. Повреждённый state восстанавливается через `terraform import`. На пяти дроплетах это десятки минут работы.

## Почему Не Запросить Права

Права были сужены намеренно. Просить их расширения ради удобства, когда задача решается без этого, обесценивает изначальное сужение. Запрос имеет смысл только если восстановление state через import станет неприемлемым по трудозатратам.

## Acceptance Criteria

- граница прав зафиксирована в durable memory
- решение и его цена записаны явно

# vpncore

Единственная нативная библиотека, с которой линкуется приложение.

## Почему один модуль, а не два

Первая попытка собирала движок и мост как два независимых AAR. Сборка падает:

```
Duplicate class go.error found in modules libxray.aar -> libxray-runtime
and tunbridge.aar -> tunbridge-runtime
```

Каждая привязка gomobile несёт собственную копию Go-рантайма, и две такие
копии не уживаются в одном APK. Поэтому обе библиотеки связываются здесь, в
одном пакете: один рантайм, один артефакт, одна контрольная сумма.

## Что внутри

| Половина | Откуда | Роль |
| --- | --- | --- |
| Транспортный движок | `github.com/xtls/libxray` | говорит по протоколу с нодой, поднимает локальный SOCKS |
| Пакетный мост | `github.com/xjasonlyu/tun2socks/v2` | переносит пакеты между TUN-интерфейсом и этим SOCKS |

Ни одна половина сама по себе туннель не поднимает. В движке нет ни строчки
работы с TUN — это проверено по исходникам, — поэтому без моста приложение
подключается к ноде, а весь трафик устройства идёт мимо туннеля.

## Экспортируемая поверхность

```
SetProtector(Protector) error   защита сокетов от петли маршрутизации
SetAssetDir(string) error       где движку искать geoip-базу
StartEngine(string) error       запуск с Xray-конфигурацией
StopEngine() error
EngineRunning() bool
EngineVersion() string
StartBridge(fd, mtu int, proxyURL string) error
StopBridge()
BridgeRunning() bool
```

Типы намеренно простые: gomobile переносит через границу языков только их.

## Два решения, которые легко потерять при правках

**Стек собирается вручную, а не через `engine.Start()`.** Точка входа
tun2socks на некорректном ключе вызывает `log.Fatalf`, то есть завершает
процесс. На телефоне это не «не удалось подключиться», а «приложение
исчезло». Поэтому `StartBridge` повторяет то, что делает `engine.netstack`,
но возвращает ошибку.

**Уровень лога моста зафиксирован на `warning`.** По умолчанию мост пишет
каждое соединение на уровне info — это ровно та история посещений, которую
запрещает хранить модель приватности.

## Сборка

Локально не собирается: на машине разработчика нет Go. Сборка идёт в
`.github/workflows/android-build.yml` через `gomobile bind`, результат
кэшируется по содержимому этой папки.

`go.sum` в репозитории нет: он генерируется в CI командой `go mod tidy`.
Прямые зависимости зафиксированы точными версиями в `go.mod`, косвенные
выводятся из них детерминированно, но проверки целостности пока не
зафиксированы в репозитории. Это известный пробел, закрывается фиксацией
`go.sum`, как только на сборочной машине появится Go.

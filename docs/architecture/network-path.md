# Сетевой Путь До Площадки

Документ о том, почему рабочий код может не работать, и почему выбор хостинга для входных нод — не вопрос цены.

## Что Произошло

Клиент, нода и конфигурация были проверены и исправны. Через ноду в Амстердаме (DigitalOcean), с той же конфигурацией приложения, из конвейера GitHub скачивалось 5 МБ за 4,1 секунды — 1,2 МБ/с.

С телефона в российской сети через ту же ноду не проходило ничего.

Затем тот же самый APK, отличающийся **только адресом точки входа**, был направлен на обычный VDS в Финляндии.

| Измерение за сессию | DigitalOcean, Амстердам | VDS, Финляндия |
| --- | --- | --- |
| Пакетов от устройства | 1 966 | 30 830 |
| Пакетов обратно | 947 | 27 394 |
| Живых TCP-соединений | 5 | 126 |
| Ошибок движка | 276 | 0 |
| Разрешено имён | 0 | 128 |

Код не менялся между этими двумя запусками ни на строку.

## Что Это Значит

Российские операторы фильтруют трафик оборудованием глубокой инспекции пакетов. Оно не блокирует адреса хостингов целиком — это было бы слишком заметно и задело бы обычные сервисы. Оно **деградирует длинные объёмные потоки** к адресам с плохой репутацией.

Наблюдаемая картина именно такая:

- TCP-соединение устанавливается
- рукопожатие TLS проходит
- страница в несколько килобайт открывается
- непрерывный поток умирает почти сразу

Отсюда важное следствие для диагностики: **проверка «сайт открывается» ничего не доказывает**. Она передаёт единицы килобайт. Проверять надо устойчивую загрузку — в конвейере это делает шаг `Verify the tunnel sustains a download`, который качает 5 МБ и падает, если тело пришло не целиком.

## Перебор Регионов: Ни Один Не Годится

Первая мысль была, что дело в амстердамском диапазоне. Проверено: по одной машине в шести регионах, каждая отдаёт один и тот же файл в 5 МБ, замер из российской сети.

| Регион | Скачано за 30-45 с | Скорость |
| --- | --- | --- |
| `ams3` Амстердам | 33 КБ | 1,1 КБ/с |
| `fra1` Франкфурт | 33 КБ | 1,1 КБ/с |
| `lon1` Лондон | 33 КБ | 0,7 КБ/с |
| `nyc3` Нью-Йорк | 33 КБ | 0,7 КБ/с |
| `tor1` Торонто | 18 КБ | 0,4 КБ/с |
| `sfo3` Сан-Франциско | 18 КБ | 0,4 КБ/с |
| **VDS в Финляндии** | **5 МБ целиком** | **192 КБ/с** |

Разница — **в двести с лишним раз**, и она не зависит ни от континента, ни от расстояния: Торонто и Сан-Франциско душатся сильнее Амстердама, хотя дальше.

**Признак, по которому это узнаётся.** Обратите внимание на одинаковость: 33 КБ, 33 КБ, 33 КБ. Поток не замедляется плавно, как при перегрузке канала. Проходят первые несколько десятков килобайт, после чего он мёртв. Перегрузка так не выглядит; так выглядит решение, принятое по адресу назначения.

Вывод: ограничение не региональное. Оно относится к адресному пространству провайдера целиком.

## Почему Именно Крупный Хостинг

Дело не в качестве площадки. Дело в репутации диапазона адресов.

Диапазоны крупных облачных провайдеров годами используются VPN-сервисами. Обычный VDS в диапазоне небольшого провайдера такой истории не имеет. Отсюда 3 МБ/с против нуля при прочих равных.

Это не свойство DigitalOcean как компании: это свойство того, как её адреса выглядят со стороны фильтрующего оборудования.

## Что Из Этого Следует Для Архитектуры

**Роль площадки определяет требование к её адресам.**

| Роль | Кто с ней соединяется | Требование к диапазону |
| --- | --- | --- |
| Core, база, метрики, бэкапы | наши же машины | нет |
| Входная нода | устройства пользователей в России | диапазон должен быть чистым |

Крупное облако полностью пригодно для всего, кроме входных нод. Для входных нод пригодность определяется измерением, а не выбором провайдера по прайс-листу.

`ADR-005` уже фиксировал второго провайдера нод как открытое решение. Этот документ переводит его из «желательно для отказоустойчивости» в «обязательно для работоспособности».

## Как Проверять Площадку Перед Использованием

Годность диапазона нельзя выяснить из документации провайдера. Её измеряют:

1. Поднять машину, отдающую файл в 5 МБ.
2. Скачать его **из российской сети** — с устройства или с сервера в России.
3. Сравнить со скоростью того же файла с заведомо рабочей площадки.

Для перебора регионов одного провайдера есть workflow `Region Sweep`: он ставит по одной машине в каждый регион, каждая отдаёт одинаковый файл, и удаляет их все. Тарификация посекундная, весь перебор стоит центы при условии, что удаление отработало — оно запускается первым при любом действии.

## Ловушка Измерения

Сервер в России, взятый как измеритель, может иметь собственную фильтрацию, отличную от потребительской сети. Наш `ru` не резолвит домены DigitalOcean и не может выйти на порт 8080, при этом качает с Cloudflare на 10 МБ/с. Такой измеритель годится для грубого отсева, но окончательное подтверждение даёт только устройство в той сети, где будут пользователи.

## Что Это НЕ

Чтобы не искать причину повторно:

- не дефект клиента — тот же APK работает через другую площадку
- не дефект ноды — та же нода отдаёт 1,2 МБ/с из конвейера
- не конфигурация движка — проверена тремя вариантами
- не сертификат, не DNS, не маршрутизация

Всё перечисленное было проверено по очереди и исключено. Разница ровно одна: адрес, к которому подключается устройство.

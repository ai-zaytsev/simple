## Постоянный Хост Сайта

Решение Business Owner от 29.08.2026:

| Свойство | Значение |
| --- | --- |
| Имя | `site-1` |
| Роль | официальный сайт `simple-vpn.download` |
| Регион | `ams3` |
| Размер | `s-1vcpu-512mb-10gb` — 1 vCPU, 512 МБ, 10 ГБ |
| Цена | $4/мес |
| Публичные порты | только 80 и 443 |
| SSH | ключ установлен для recovery, публичный порт 22 закрыт DigitalOcean Firewall |

`site-1` — первый постоянный Droplet в DigitalOcean. `Deploy APK Site` перед первым apply заново читает `/v2/droplets` и отказывает, если список не пуст. После создания тот же guard принимает только один известный `site-1`; неизвестный сосед превращает apply в отказ, а не в молчаливое расширение расходов.

Живая инвентаризация и Terraform state отвечают на разные вопросы. Перед первым deploy provider показал ноль, но state ещё содержал запись уже удалённой тестовой ноды и пустую привязку к проекту. Workflow удаляет из state только эти два адреса и только после provider-confirmed `droplets=0`. Перед любым plan все IP, уже записанные в state, маскируются: refresh способен напечатать адрес удалённой машины раньше, чем новый ресурс вообще появится.

## Правило Проверки Доступа

**Работоспособность токена проверяется теми эндпоинтами, которые реально используются, и никогда — эндпоинтом идентичности или метаданных.**

Это правило появилось после двух одинаковых ошибок:

- Cloudflare: проверка через `GET /user/tokens/verify` дала `401` на полностью рабочем токене, потому что он не имел права читать метаданные самого себя
- DigitalOcean: проверка через `GET /v2/account` дала `403` на полностью рабочем токене, потому что он не имел права читать данные аккаунта

В обоих случаях правильно суженный токен выглядел сломанным. Проверка, наказывающая за корректное ограничение прав, хуже отсутствия проверки: она провоцирует расширить права, чтобы «починить» диагностику.

Право записи проверяется созданием и немедленным удалением тега. Теги бесплатны и не несут ресурсов — это единственный способ узнать про запись, не создав платный объект.

### Шифрование

DigitalOcean шифрует данные Spaces на диске алгоритмом AES-256 по умолчанию и не предоставляет настройку шифрования на уровне bucket. Поэтому `get-bucket-encryption` отвечает ошибкой, и это не признак проблемы. Требование о шифровании выполняется платформой.

Дополнительно: бэкапы PostgreSQL шифруются на стороне Core до загрузки. Шифрование провайдером защищает от изъятия диска у провайдера, но не от доступа к самому bucket по ключам.

### Границы Прав Ключей Spaces

Установлено запуском `Spaces Configure` с `apply=true` 2026-08-22.

| Операция | Результат |
| --- | --- |
| `PutObject`, `GetObject`, `DeleteObject` | Работают |
| `HeadBucket`, `ListObjectsV2` | Работают |
| `PutBucketVersioning` | `AccessDenied` |
| `PutBucketLifecycleConfiguration`, обе формы | `AccessDenied` |

Ключи дают объектный доступ и не дают настраивать сам bucket. Это ограничение ключа, а не bucket: в панели DigitalOcean ключам Spaces выдаётся уровень доступа, и настройка bucket требует более широкого, чем чтение и запись объектов.

### Retention Без Расширения Прав

Расширение прав **не запрашивается**. Требуемый retention достигается без него:

| Требование | Как выполняется |
| --- | --- |
| Шифрование | Платформой, AES-256 по умолчанию, плюс шифрование бэкапа на стороне Core до загрузки |
| Retention бэкапов | Само бэкапное задание удаляет объекты старше окна хранения. Требует только `DeleteObject`, который есть |
| Отсутствие затирания бэкапов | Ключи объектов содержат метку времени, поэтому перезаписи не происходит и versioning для этого не нужен |
| Проверка восстановления | Отдельная задача восстановления из бэкапа, а не факт наличия файла |

Чего это не даёт: истории версий для state Terraform. Повреждённый или потерянный state восстанавливается через `terraform import`. На флоте из пяти дроплетов это работа на десятки минут, а не катастрофа.

Запрашивать более широкий ключ имеет смысл только если эта работа станет неприемлемой. Просить права, без которых задача решается, противоречит смыслу изначального сужения ключей.

### APK В Spaces

Официальные APK используют отдельный namespace `apk/` в существующем `simple-vpn-infra-backups`:

| Ключ | Смысл | Перезапись |
| --- | --- | --- |
| `apk/releases/<version>/simple-vpn-<version>.apk` | постоянная версия | запрещена workflow |
| `apk/latest/simple-vpn.apk` | указатель на последнюю версию | после успешной versioned upload |
| `apk/releases.json` | публичный список и метаданные | после `latest` |

Listing bucket остаётся приватным. `public-read` получают только эти objects; Terraform state и PostgreSQL backups остаются приватными. Для `apk/releases/` нет lifecycle expiration, а publication workflow вообще не имеет операции delete.

### Что Делает Workflow `Spaces Configure`

Пытается включить versioning и lifecycle, не прерываясь при отказе, и в любом случае выполняет round-trip: запись, чтение обратно, удаление. Хранилище, в которое ни разу не писали, целью бэкапа не является.

При отказе в настройке bucket в summary печатаются оба варианта продолжения, чтобы решение принималось по фактам, а не по умолчанию в сторону расширения прав.

### Почему Bucket Настраивается Не Через Terraform

В этом bucket лежит state самого Terraform. Управлять им из Terraform — цикл начальной загрузки. Хранилище состояния настраивается вне инструмента, чьё состояние оно хранит.

## Границы Бюджета

Расходы DigitalOcean, включая Spaces, не превышают $45/мес. Плановая конфигурация — $31/мес, см. [../architecture/mvp-topology.md](../architecture/mvp-topology.md).

- autoscaling и любое автоматическое увеличение платных ресурсов не настраиваются
- добавление дроплета сверх плановых — решение Business Owner
- при приближении расхода трафика к 3000 GiB срабатывает алерт, а не расширение

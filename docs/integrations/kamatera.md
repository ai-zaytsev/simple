# Kamatera

Production-провайдер расходуемых VPN-нод. Фактические ноды, регион, размеры, домены, состояние и recovery находятся только в [BO-инструкции](../business-owner-operations.md); этот документ фиксирует технический контракт API и автоматизации.

Площадка была выбрана после проверки устойчивой загрузкой из российской сети: короткий ответ «сайт открывается» не обнаруживал ограничение длинных потоков у предыдущей площадки. История измерения — в [network-path.md](../architecture/network-path.md).

## Доступ

API credentials хранятся только в GitHub Secrets. Аутентификация — заголовки `AuthClientId` и `AuthSecret`. Отдельного credential-check endpoint нет, поэтому годность проверяется чтением списка машин: `200` доказывает доступ, даже если список пуст.

Ключи недоступны Android, продуктовым логам и документации. Provider response никогда не печатается целиком: при создании он может содержать root password.

## Штатные Workflows

`Add Server` — единственный production-путь создания ноды: выбирает одобренный provider option, создаёт instance, выполняет cloud-init, DNS/TLS, регистрирует ноду в Core и оставляет её вне выдачи до проверок.

`Node Inspect` проверяет конкретную ноду через Core как jump host. `Retire Node` выводит и удаляет ноду только после lifecycle-перехода. Диагностический `Kamatera Node` используется для read-only inventory/options и ограниченных provider probes; он не заменяет production lifecycle.

После create/destroy workflow обязательно печатает обезличенный счётчик оставшихся машин. Неожиданный ресурс — расход и инцидент инвентаря, а не «запас».

## Правило Приёмки Площадки И Ноды

Provider пригоден только после устойчивой загрузки не менее 5 МБ из целевой российской сети. Production-нода дополнительно требует:

1. успешного provisioning и heartbeat;
2. TLS/cover/VPN/edge проверок со стороны Core;
3. проверки подключения и privacy с Android в целевой сети;
4. явного `serving`, а не автоматического включения после создания машины.

Порог «5 МБ» проверяет путь провайдера, но не доказывает доступность конкретного IP на следующий день. Поэтому device checks остаются постоянной частью lifecycle.

## Почему Provider Response Не Печатается

При создании provider возвращает generated root password. Из ответа извлекаются только названные поля, а чувствительные значения маскируются до любых других действий. Для диагностики формы допустимо вывести только имена полей:

```text
status field not found; fields present: id, status, description
```

Полный body, headers, credentials, IP пользователя и адреса посещённых сайтов не являются диагностическим выводом.

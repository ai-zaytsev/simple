# Kamatera

Кандидат на площадку для входных нод. Не production-провайдер: проверяется.

Причина, по которой понадобился второй провайдер, — [../architecture/network-path.md](../architecture/network-path.md). Коротко: все шесть проверенных регионов первого провайдера отдают в российскую сеть несколько десятков килобайт и умолкают, обычный VDS отдаёт файл целиком в двести раз быстрее. Ограничение относится к адресному пространству, а не к региону, поэтому решается только сменой площадки.

## Доступ

| Что | Где |
| --- | --- |
| `KAMATERA_ACCESS_KEY` | секрет репозитория |
| `KAMATERA_SECRET_KEY` | секрет репозитория |

Аутентификация — два заголовка, `AuthClientId` и `AuthSecret`. Отдельного эндпоинта для проверки ключей нет, поэтому годность проверяется обращением к списку машин: `200` означает, что ключи работают, даже если список пуст.

Ключи доступны только из конвейера. С машины разработчика API этого провайдера недоступен — как и у остальных, это осознанно.

## Workflow `Kamatera Node`

| Действие | Что делает |
| --- | --- |
| `list` | что работает прямо сейчас |
| `options` | какие датацентры и образы можно запросить |
| `create` | одна машина с именем `simple-vpn-candidate` |
| `destroy` | удаляет машины с этим именем |

После любого действия печатается счётчик оставшихся машин. Это не украшение: **тарификация почасовая**, и забытая машина тратит деньги тихо. Счётчик — единственный способ узнать это, не заходя в панель.

`options` запускается первым при работе с новым датацентром: идентификаторы образов у этого провайдера не угадываются, и создание с выдуманным образом тратит прогон впустую.

## Почему Не Terraform

Кандидат, который проверяется, — это инструмент, а не инфраструктура. Записать его в то же состояние, где живут настоящие ноды, значит смешать проверяемое с работающим: любое `apply` начнёт считать его частью флота.

Если провайдер пройдёт проверку, он описывается нормально — Terraform, cloud-init, всё как у остальных. До этого момента машина создаётся вызовом API и удаляется тем же вызовом.

## Правило Приёмки Площадки

Из `ADR-029`: пригодность определяется измерением из российской сети, а не прайс-листом.

Измерение — **устойчивая загрузка не менее 5 МБ**. Проверка «сайт открывается» непригодна: она передаёт единицы килобайт, а фильтрующее оборудование пропускает первые десятки килобайт любого потока. Именно поэтому все наши проверки были зелёными на неработающей площадке, пока в конвейер не добавили загрузку 5 МБ.

## Ответ На Создание Не Печатается

При создании машины провайдер возвращает в теле ответа **сгенерированный пароль root**. Шаг, печатавший ответ целиком ради отладки, положил этот пароль в публичный лог сборки.

Машина была уничтожена сразу — после удаления пароль ничего не открывает, — но правило из этого следует общее и относится не только к этому провайдеру:

**Ответ внешнего API не печатается целиком никогда.** Из него достаются названные поля. Что провайдер решит вложить в ответ, заранее неизвестно, и «посмотрим, что там пришло» — это публикация чужого решения о содержимом.

Когда ответ нужно диагностировать, печатается **набор полей, а не значения**:

```
status field not found; fields present: id, status, description
```

Этого достаточно, чтобы понять форму ответа и поправить разбор, и невозможно случайно опубликовать содержимое.

Пароль дополнительно маскируется сразу после получения ответа — до любого другого действия. Маскирование здесь вторая линия, а не первая: первая — не печатать.

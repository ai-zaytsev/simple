# Блокеры Релиза

Список того, что **обязано** быть сделано до выкатки. Не «желательно», не «когда дойдут руки»: пока здесь есть незакрытый пункт, релиза не будет.

Отдельный документ, а не строчка в задачах фичи, потому что задачи фичи закрываются вместе с фичей, а эти пункты переживают её и должны попадаться на глаза.

## VIP Ни Разу Не Исполнялся

**Статус:** открыт. Обнаружено 2026-08-29 при попытке ответить, завершена ли стадия 23.

VIP-аккаунтов ноль. На панели: `VIP | 0 | без предела | без предела | без предела`. Политика записана и видна из строк базы, но **ни один из путей VIP никогда не выполнялся** — ни снятие ограничения скорости, ни отсутствие предела на устройства, ни выпуск внешних ссылок.

Из-за этого висит приёмка трёх стадий:

| Стадия | Критерий | Чего не хватает |
| --- | --- | --- |
| 21. FREE и VIP | войти с другого устройства и получить тот же VIP | VIP-аккаунта |
| 22. Роутеры и TV | добавить TV и роутер, отключить только TV | VIP-аккаунта |
| 23. Скорость | у VIP нет ограничений | VIP-аккаунта |

**Почему аккаунт до сих пор не заведён.** `SetAccountTier` работает по email-адресу, а входные параметры `workflow_dispatch` попадают в заголовок запуска. Правило Business Owner — не выводить адреса в публичные логи Actions — не оставляет безопасного пути.

**Почему это блокер, а не долг.** «Политика записана» и «VIP работает» — разные утверждения, и за один день дважды выяснялось, что второе из первого не следует: ограничитель скорости стоял верно и не работал в одну сторону, диагностика отвечала наоборот. Продавать тариф, ни один путь которого не исполнялся, — это выкатывать то, что никто не открывал.

**Закрывается:** тариф назначается по идентификатору аккаунта (идентификаторы уже пригодны для логов — `tier.go` пишет их намеренно, адреса никогда), после чего проходится приёмка всех трёх стадий на живом VIP.

## Путь Входа Один И Не Проверен Оттуда, Откуда Важно

**Статус:** открыт, причина найдена 2026-08-30. Обнаружено 2026-08-29 сразу после того, как панель научилась отличать путь входа от запаса.

```
| №4 | путь входа | works | отсюда 100% | с устройств — | проверок 0 |
```

Живой подписанный bootstrap содержит не один, а четыре entry: стабильный домен, прямой IP и два HTTPS edge. Панель показывала ровно один из-за blind spot в измерении: Core сам проверял только `https-direct`, Android проверял домены VPN-нод, но не перебирал entry Control Plane, а серверная allowlist отбрасывала device report по IP и edge.

«Отсюда 100%» значит, что мы достаём сами себя. Про доступность из России это не говорит ничего — ради этого различия и заведены две точки обзора, и оно уже один раз показало блокировку, невидимую изнутри.

**Чем рискует.** Устройство спрашивает путь входа, когда ему нужно узнать, куда идти дальше: первая установка, смена нод, восстановление после блокировки. Уже подключённые живут на выданном плане и ничего не заметят — а новая установка не заработает вовсе. Отказ выглядит как «приложение не работает у новых пользователей», при полностью здоровом сервисе.

На 2026-08-30 из внешней точки сначала отвечали стабильный домен, прямой IP и один edge. У `n-c5e6` оказался остановлен `nginx`: management SSH и сама нода оставались живы, а её публичный edge получал connection refused. Штатный `Update Node` дополнен восстановлением HTTPS-сервиса и применён с rollback-таймером; после его health/privacy checks все четыре точных bootstrap URL отвечают HTTP 200 с валидным TLS. Новая нода не нужна: уже есть четыре рабочих маршрута, в том числе edge на отдельных нодах; добавление пятого адреса не исправляло бы отсутствие измерения.

**Исправление:** Android ограниченно по частоте проверяет каждый entry из последнего подписанного descriptor напрямую из пользовательской сети и отправляет только `host` нашего entry, результат и latency. Core принимает только цели из собственной таблицы включённых bootstrap entries/нод. Попытки через VPN в эту метрику не входят.

**Закрывается:** test APK проверен на целевом устройстве из России, неисправный entry восстановлен либо выключен, и живая панель показывает device checks у каждого оставшегося включённого пути.

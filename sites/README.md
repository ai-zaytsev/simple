# Cover Sites

Страницы, которые открываются на входных доменах при обычном HTTPS-запросе.

## Почему их несколько

Одинаковый файл на нескольких доменах делает их одной группой при простом сравнении: посчитал хэш — и вот список наших доменов. Раньше так и было: две ноды отдавали побайтово одинаковую страницу.

Варианты отличаются не подставленным заголовком, а целиком: другая тема, другая вёрстка, другой стиль, другой шрифт, другая структура разметки. Подстановка заголовка в общий шаблон оставила бы одинаковыми CSS, структуру и формулировки — то есть всё, по чему страницы кластеризуются, кроме первой строки.

Это не защита. Связать домены можно другими способами; смысл в том, чтобы это не делалось тривиально.

## Общие требования ко всем вариантам

**Ни одного внешнего запроса.** Ни шрифтов, ни аналитики, ни картинок с других хостов. Три причины: нода остаётся самодостаточной, посетитель не утекает третьим сторонам, и у страницы нет исходящих соединений, по которым её можно связать с другими нашими доменами.

**Никаких упоминаний продукта.** Ни текстом, ни ссылками, ни метаданными.

**Читаемое содержание.** Заглушка выдаёт себя сразу: страница «сайт в разработке» на домене, к которому кто-то держит долгоживущее TLS-соединение, — это подтверждение, что домен служебный. Поэтому текст написан так, чтобы его можно было прочитать до конца.

**Статика без зависимостей.** Один файл, встроенный CSS, отдаётся Nginx без интерпретации.

## Варианты

| Каталог | Тема | Где |
| --- | --- | --- |
| `pigeons` | городские голуби | нода `n-7f3a` |
| `trams` | закрытые трамвайные линии | нода `n-2b91` |
| `sourdough` | домашняя закваска | свободен, для следующей ноды |
| `syncbridge` | страница Control Plane | `simple-syncbridge.download` |

Новой ноде даётся вариант, которого ещё нет в работе. Когда варианты кончатся, пишется следующий, а не переиспользуется старый.
